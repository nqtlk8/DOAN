### B1. 3 Integration Test mới sai schema → chắc chắn fail khi có Docker
Các test này chưa từng chạy (sprint doc ghi Testcontainers không kết nối được Docker), nên lỗi fixture không bị phát hiện. Kết quả khi chạy **đúng các câu INSERT trong test** trên PostgreSQL:

| Test | Câu lệnh trong test | Lỗi thật từ PostgreSQL |
|---|---|---|
| `AnalyticsDataAdapterPostgresIT` | `INSERT INTO customer (id, code, name, branch_id) VALUES (999, ...)` | `column "code" of relation "customer" does not exist` (cột thật là `customer_code`; `customer.id` là **uuid**, không phải số) |
| `AnalyticsDataAdapterPostgresIT` | `INSERT INTO product (id, code, name) ...` | `null value in column "is_active" of relation "product" violates not-null constraint` (còn thiếu `category_id`, `base_unit`, `created_at`, `updated_at`) |
| `AnalyticsDataAdapterPostgresIT`, `StockAlertApiPostgresIT` | `INSERT INTO stock_movement (id, product_id, branch_id, quantity) ...` | `null value in column "movement_type" ... violates not-null constraint` (còn thiếu `ref_type`, `ref_id`; `branch_id` 98/77 không tồn tại → vi phạm FK) |
| `StockAlertApiPostgresIT` | `INSERT INTO branch (id, code, name) ...` | `null value in column "is_active" of relation "branch" violates not-null constraint` |
| `SnapshotReplicationPostgresIT` | `INSERT INTO stock_on_hand (product_id, branch_id, quantity, created_at, updated_at) ...` | `null value in column "is_deleted" ... violates not-null constraint` (thiếu `id` uuid, `version`) |
| `SnapshotReplicationPostgresIT` | `INSERT INTO receivable_debt (customer_id, branch_id, total_debt, ...)` | `null value in column "is_deleted" ...` (thiếu `id`, `version`; `customer_id` `1111...` không tồn tại → FK) |

Ngoài ra `AnalyticsDataAdapterPostgresIT.testFetchDashboard_withNullBranchId/withBranchId` **không có assert** — chỉ chứng minh "không ném lỗi".

### B3. Chưa đối soát dữ liệu lịch sử `stock_movement` ở HQ (cần kiểm tra trên Docker thật)
Cảnh báo ở HQ tính từ `stock_movement` (D-07). Nhưng `setup-replication.sh` tạo subscription HQ với `copy_data = false` → movement phát sinh ở chi nhánh **trước** khi bật replication không có ở HQ. Trong khi đó `stock_on_hand` vừa được copy đủ (`copy_data = true`). Sprint FD-5 ghi "trùng khớp **cho các phát sinh mới**" — tức dữ liệu cũ có thể lệch, và cảnh báo sẽ sai với các sản phẩm đó.
Chạy tại HQ (`docker exec -it code-hq-db-1 psql -U erp_user -d erp_hq`):
```sql
WITH mv AS (SELECT product_id, branch_id, SUM(quantity) AS q FROM stock_movement GROUP BY 1, 2)
SELECT COALESCE(mv.product_id, s.product_id) AS product_id,
       COALESCE(mv.branch_id,  s.branch_id)  AS branch_id,
       mv.q AS tong_movement, s.quantity AS stock_on_hand
FROM mv FULL JOIN stock_on_hand s ON s.product_id = mv.product_id AND s.branch_id = mv.branch_id
WHERE COALESCE(mv.q, 0) <> COALESCE(s.quantity, 0)
ORDER BY 2, 1;
```
Kết quả rỗng → OK. Có dòng → cần quyết định (xem câu hỏi Q1 cuối file).
