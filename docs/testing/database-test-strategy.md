# Database Testing Strategy

## Current State (Gate 0)
Current testing infrastructure:
- **Flyway**: Disabled in test profile (`spring.flyway.enabled=false`).
- **Schema Generation**: Hibernate generates the schema automatically (`spring.jpa.hibernate.ddl-auto=create-drop`).
- **Database**: H2 in-memory database (`jdbc:h2:mem:testdb_${random.uuid}`).
- **Test Suite**: Approximately 133 tests currently rely on this fast, in-memory setup.

## Target Architecture

The testing infrastructure will be divided into the following layers to ensure fast feedback while providing production-like safety guarantees:

### 1. Fast Test Suite
- **Environment**: H2 in-memory database.
- **Schema**: Generated by Hibernate (`ddl-auto: create-drop`).
- **Scope**: Retain the existing ~133 tests here. These tests verify Java/Spring logic and mocks quickly without the overhead of real databases or migrations.

### 2. PostgreSQL Integration Suite
- **Environment**: Testcontainers with real PostgreSQL (pinning major version to match production, e.g., PostgreSQL 16).
- **Schema**: Managed exclusively by Flyway (`V1 -> Vcurrent`).
- **Hibernate**: Configured to validate the schema (`ddl-auto: validate`), NOT to create it.
- **Scope**: Verify that the actual PostgreSQL schema (including native types and extensions) is compatible with Hibernate mappings, and test complex queries or constraints (like unique idempotency keys) that H2 cannot fully replicate.

### 3. Flyway Migration Suite
- **Environment**: Testcontainers with real PostgreSQL.
- **Scope**:
  - **Fresh Install**: Verify migrations apply cleanly from empty database to `Vcurrent`.
  - **Upgrade/Data Migration**: Verify that applying a new migration against a database populated with existing data (e.g., from `V(current-1)`) succeeds without breaking non-null constraints, dropping data, or corrupting existing records.
